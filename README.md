# 流光 Liuguang

Flutter Android 多仓视频播放器。首页／电视／我的三栏，包含订阅管理、搜索、选集播放、直播节目单、收藏历史、扫码导入、备份恢复和局域网订阅推送。

> 开发中。配置能导入、测试通过、APK 构建成功和真实源能播放是不同的验证层级。当前不能承诺所有第三方插件或外部服务可用。

## 云端编译与测试

本项目使用 [GitHub Actions](https://github.com/wanan8396/liuguang/actions/workflows/android-ci.yml) 编译与测试，无需在用户电脑上编译。

每次推送或 PR 自动运行：

1. Flutter 静态分析与离线单元／组件测试。
2. Android JVM 回归测试和 ARM64 APK 构建、签名校验、SHA-256。
3. x86_64 Android 模拟器上的受控 DEX、初始化／关闭、端口冲突测试。

运行成功后，从对应 Actions run 的 **Artifacts** 下载 `liuguang-arm64-<commit>`。包内包含 APK、校验值和构建元数据。

- Android 7.0 / API 24 及以上，ARM64。
- CI 产物使用临时开发签名，**不是正式发布签名**。不同 runner 的测试包可能无法直接覆盖安装；先导出个人数据，再根据 Android 提示处理签名冲突。
- x86_64 模拟器不执行 ARM-only QuickJS 测试，跳过状态在报告中明确展示。
- CI 不抓取真实订阅、不执行第三方远程插件、不访问账号或媒体；不能将 CI 绿灯当成真实源播放验收。

固定工具链：Flutter 3.47.8 / Dart 3.13.7、JDK21、Android SDK36、NDK28.2.13676358、Gradle wrapper 9.3.1。依赖由 `pubspec.lock` 和 Android 构建配置锁定。

## 使用

1. 首次打开自动获取内置奇奇多仓 `http://z.qiqiv.cn/123.txt` 及全部子仓。后续启动在后台检查更新，间隔6小时；应用运行期间每6小时检查一次。更新失败保留已有配置，后台刷新不切换正在使用的内容源。
2. 选择仓库和站点；导入的订阅自动信任，JAR / JavaScript 插件直接加载，无需手动确认。

订阅管理每次输入一个地址，点击“追加订阅”后清空输入框，可继续添加下一个；已有订阅和当前源保留，重复地址跳过。需要重新获取内容时使用“更新”或“全部刷新”。多个视频订阅独立保存，可重命名或移除。选择内容源时可按订阅筛选仓库，也可搜索内容源。直播订阅同样逐个追加。

全网扫描入口已移除。内置订阅在后台维护，不显示订阅卡片、地址或导入日志。视频订阅页只管理用户自己追加的地址，支持单条删除和清理旧订阅，收藏与观看历史保留。

电视页汇总所有已订阅仓库与独立直播订阅，最多4个来源并发加载，频道增量显示。占位地址和失败来源集中在“来源状态”，不会遮住已有频道；刷新失败保留当前运行期间该来源上次成功的频道。跨仓库频道及其收藏保留原插件归属。

“关于流光”介绍影视、短剧、电视直播、收藏续播与倍速功能。应用不收集运行日志，播放器调试转发及宿主插件日志输出已关闭；必要的操作失败提示仍保留。第三方插件自身行为由其实现决定。

插件直接创建的 Android 扫码、网盘与状态窗口继承统一的 Material 圆角主题，支持系统浅色/深色模式；保留插件原有按钮行为和状态文本。

播放器右下角提供 0.5x–3.0x 倍速入口，选择浮层就近显示在按钮上方；长按画面临时切到 2x，松手、手势取消或切后台恢复原速度。直播与从头播放不再主动定位到 0，非致命的流不可定位提示不会遮住画面。真实的解析、连接和解码错误仍会显示，直播列表与点播错误独立管理。
已下载当前架构代理文件的兼容插件，重新初始化时不再自动弹出 SO 状态窗口；手动状态查询和下载按钮仍然保留。
3. 浏览分类或搜索，进入详情选择线路与集数。
4. 需要账号的源，在“源管理与凭据”配置对应名称的 Cookie/Token；应用不自动注册、付费或绕过服务端授权。
5. 数据推送需要主动开启，同 Wi-Fi 设备输入配对码，手机确认后才导入，超时自动关闭。

无可用源、缺凭据、外部 HTTP/TLS 故障和插件异常会分别显示，失败不会被伪装成空列表成功。

## 功能与结构

- `lib/core/config`：宽松 JSON、gzip、Base64、Hex/AES 包装、多仓／单仓、循环与镜像识别。
- `lib/core/network`：有界请求、中文域名、UA、重定向和资源引用解析。
- `lib/core/engine`、`pigeons`：CMS/远程接口、类型化原生通道和播放调度。
- `android/source_engine`：CatVod/JAR、QuickJS/drpy、WebView、流式回环代理。
- `lib/core/live`：M3U/TXT/JSON、XMLTV/JSON 节目单。
- `lib/core/storage`：Hive、安全凭据、恢复前快照。
- `lib/features`：真实数据驱动的界面和 media_kit 播放控制。

## 端口兼容与已知限制

动态回环代理是常规路径。旧插件可能硬编码 9978、9997 或 5266；这些端口的兼容能力与插件初始化分别管理，不应因为一个不相关端口绑定失败阻断所有源。

- 固定端口无法占用时，不连接或接管其他进程服务，也不终止其他应用。
- 硬依赖被占端口的插件仍可能失败，需要具体端口诊断，不能保证透明迁移任意 JAR 的硬编码请求。
- `5266/iptv.m3u` 特定客户端聚合服务尚未完整实现。
- 任意 JS 方言、旧 QuickJS 字节码、自定义 JAR jsapi、Python/Node 可选运行时未全部覆盖。
- Android 14+ 的旧版 JNI 插件在初始化期间创建 `DexClassLoader` 时，宿主先将应用私有目录中属于自身的二次 DEX 文件设为只读，再交给系统加载；初始化返回或抛出异常后恢复当前线程的 JNI 调用表，无需 root。外部路径仍受系统检查。
- 旧插件再次写入缓存中同名的只读 DEX 时，创建新的文件节点，避免覆盖 ART 已映射的旧文件；适配状态限于初始化线程，普通只读配置保持原样。
- JPJ 旧插件的备用域名需返回有效 JSON 后才使用；兼容其代理端口发现方式，使用宿主已经绑定的动态本机端口。
- 播放器访问本机媒体代理时不发送上游 `Origin`，上游与字幕请求仍保留源站请求头；HLS 分片及密钥的相对地址以重定向后的最终清单地址解析。
- 播放超时与源引擎保持45秒，避免插件准备清单超过默认5秒便失败。支持插件返回清晰度/URL数组，以及旧9997端口的 `/m3u8?url=` 包装。
- 小虎斑已失效的全网短剧固定接口会转到同仓已启用的短剧备用源，页面显示实际来源；上游发布新接口后不触发旧地址兼容规则。
- 真实第三方插件、网页认证、音画、首帧、手势和续播仍需 ARM64 设备验收。

## 隐私与插件信任

远程 JAR/JS 在应用权限下执行，不是安全沙箱。仅添加可信订阅；MD5 可检查制品一致性，但不证明作者身份或安全性。

凭据使用系统安全存储，不进入普通备份。订阅新增、刷新和备份恢复后均自动信任插件；旧版的手动信任记录不再生效。默认媒体代理只绑定 loopback；局域网推送是独立、限时、需要配对确认的服务。TLS 校验不会因兼容问题被关闭。

## 安装包体积

交付使用 `flutter build apk --release --split-per-abi --target-platform android-arm64`。调试包包含 JIT 数据、调试引擎、Vulkan 校验层和额外架构的原生依赖，不能用于衡量最终体积。本次实测从 164.3 MB 调试包降至约 46.0 MB ARM64 release 包；保留视频解码、扫码和 JS/JAR 插件能力，播放器与 Flutter 原生引擎占主要体积。
